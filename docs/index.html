为什么不用现成的媒体服务器

Jellyfin、Plex 那类东西很强大，代价是安装、开机自启、转码发热、账号体系。这个工具只做一件事：把本机文件交给同一张 WiFi 下的手机。

自由指定内容

可以是整个剧集目录、整个相册，也可以是三个散装文件。加错了随时移除，位置会被记住。

照片墙

目录里的图片自动排成缩略图网格，点开全屏、左右滑动翻页。服务端生成缩略图并缓存，几百张也不卡。

PDF 漫画

PDF 逐页渲染成图片，全屏阅读、滑动翻页、跳到指定页。翻过的页会缓存，几十页的漫画也不卡。

转码缓存

装了 ffmpeg，电脑把不兼容的片子转成带索引的 MP4 缓存下来。手机浏览器里能像本地文件一样拖，下次秒开。

手机优先的界面

竖屏排版、拇指好点的行高、文件名自动截断。带搜索框，跨所有位置按名字找片。

密码 + 限速

进站先输密码，浏览器记住 30 天。连续错 5 次锁一分钟，防止室友或访客瞎猜。

拖得动进度条

实现了 HTTP Range，手机端快进、后退、断点续播都正常，不会每次从头缓冲几个 GB。

MKV 也有出路

浏览器解不了的容器，播放页会给出带账号密码的直链，粘进 VLC 就是原画质加字幕。

零依赖

只用 Python 标准库和自带的 Tkinter，不装 ffmpeg、不装浏览器驱动，拷过去就能跑。

三步，不到一分钟

没有命令行，没有配置文件。整个流程都在一个窗口里完成。

添加内容点「添加文件夹」选剧集或相册目录，或「添加视频/照片」挑几个散装文件。
点启动设一个密码，按下蓝色按钮。窗口里出现形如 http://192.168.1.8:8000 的地址。
手机打开同一 WiFi 下的手机浏览器输入地址，输密码，点片子就能看。

和现有方案比，差在哪

说实话：这个想法并不新，同类产品很多。区别只在取舍。

安全边界，写在明面上

这类工具最容易吹过头。以下是它做得到的和做不到的。

已经做到的

  • 只监听局域网，没有做任何端口映射，互联网上访问不到。
  • 所有页面都要密码，未登录只能看到登录框。
  • 连续输错 5 次锁定 60 秒。
  • 路径做了越界校验，`../` 之类的请求会被拒绝。
  • 只列出视频扩展名，其他文件不会出现在页面里。

做不到的

  • 传输是明文 HTTP。同一 WiFi 下有人刻意抓包，能看到内容和密码。
  • 不做加密存储，密码明文保存在本机配置文件里。
  • 不适合放到公网。它对“有恶意的人”没有防御，只对“好奇的室友”有效。
  • 电脑锁屏、睡眠、断网时，手机端一律打不开。

运行要求

  • Windows 10 / 11
  • Python 3.10+，自带 tkinter（官方安装包默认包含）
  • 电脑和手机在同一个局域网
  • 首次启动时在防火墙提示里勾选「专用网络」
  • 可选：装 ffmpeg 才启用电脑转码

已知限制

  • 不是独立 exe，依赖本机 Python 环境
  • 没有转码：HEVC、RMVB 这类要靠手机自己的解码能力
  • 没有海报刮削和观看记录
  • 一次只服务少量设备，面向个人使用

常见问题

手机打开一直转圈，最后说无法访问

先确认两台设备连的是同一个 WiFi，并且不是路由器的「访客网络」（访客网络通常隔离设备）。然后检查电脑的防火墙有没有放行 Python，第一次启动时那个弹窗要勾「专用网络」。最后确认窗口里的地址和 IP 没写错。

MKV 只有声音没有画面

浏览器对 MKV 容器和 HEVC 编码支持很差。用 VLC：选「打开网络串流」，把播放页下方带账号密码的直链粘进去，能原画质播放，外挂和内封字幕也正常。

能不能在外面用 4G 看

不能。地址是内网地址，只在本机所在网络有效。要远程访问需要额外的隧道工具（如 Tailscale），或者换成 Jellyfin 那类带远程访问方案的服务。不建议直接做端口映射，风险远大于便利。

会被别人看到吗

同一 WiFi 下的人能看到登录页，但看不到任何文件名，除非知道密码。要更保险，可以让手机开热点、电脑连热点，这样整个网络里只有这两台设备。
